# Essential Docker Commands for Beginners

Before diving into the commands, keep two key concepts in mind:

* **Image:** A read-only blueprint containing your application, runtime, code, dependencies, and environment configurations.
* **Container:** A running instance created from an image (the actual executing process).

---

## 1. Checking System Status & Version

### `docker version`

Displays the installed Docker client and server engine versions. Use this to verify Docker is installed and running.

```bash
docker version

```

### `docker info`

Displays system-wide statistics including total containers, images, operating system, and hardware resources.

```bash
docker info

```

---

## 2. Working with Images

### `docker pull`

Downloads an image from a container registry (like Docker Hub) to your local environment.

```bash
# Usage: docker pull :
docker pull nginx:latest

```

### `docker images`

Lists all Docker images currently stored on your local machine.

```bash
docker images

```

### `docker build`

Builds a custom image using a build configuration file named `Dockerfile` located in your project.

```bash
# Usage: docker build -t : 
docker build -t my-app:1.0 .

```

* **`-t my-app:1.0`**: Tags the image with a custom name (`my-app`) and version (`1.0`).
* **`.`**: Points to the current directory containing the `Dockerfile`.

### `docker rmi`

Deletes a local image from your system.

```bash
docker rmi nginx:latest

```

## 3. Managing Container Lifecycles

### `docker run`

Creates and immediately starts a new container from an image. This is the most frequently used command in Docker.

```bash
# Simple run:
docker run nginx

# Standard background run with custom port mapping & name:
docker run -d -p 8080:80 --name my-web-server nginx

```

* **`-d`** (*detached*): Runs the container in the background, freeing your terminal prompt.
* **`-p 8080:80`** (*port mapping*): Maps port `8080` on your host machine to port `80` inside the container. Access the application at `http://localhost:8080`.
* **`--name my-web-server`**: Assigns an explicit name to the container instead of a random generated string.

### `docker ps`

Lists active containers.

```bash
# List running containers only
docker ps

# List ALL containers (including stopped/exited ones)
docker ps -a

```

### `docker stop` & `docker start`

Stops a running container gracefully or starts an existing stopped container.

```bash
# Stop a container
docker stop my-web-server

# Start a stopped container
docker start my-web-server

```

### `docker rm`

Deletes a container. Containers must generally be stopped before deletion.

```bash
docker rm my-web-server

# Force-remove a running container immediately
docker rm -f my-web-server

```

## 4. Debugging & Interacting with Containers

### `docker logs`

Fetches stdout/stderr logs generated by the application inside the container.

```bash
# View current logs
docker logs my-web-server

# Stream live log output continuously (-f = follow)
docker logs -f my-web-server

```

### `docker exec`

Executes a new command inside an active container. Most commonly used to launch a terminal shell inside the container environment.

```bash
docker exec -it my-web-server bash

```

* **`-i`** (*interactive*): Keeps standard input open.
* **`-t`** (*tty*): Opens a pseudo-terminal session.

### `docker stats`

Streams real-time CPU, memory, and network bandwidth usage for active containers.

```bash
docker stats

```

## 5. Multi-Container Orchestration (`docker compose`)

When an app uses multiple services (e.g., a web frontend + database backend), `docker compose` manages all components declared in a `docker-compose.yml` file.

### `docker compose up`

Builds, creates, and starts all containers defined in `docker-compose.yml`.

```bash
# Start all services in the background
docker compose up -d

```

### `docker compose down`

Stops and deletes all containers, networks, and volumes initialized by `docker compose up`.

```bash
docker compose down

```

---

## 6. System Cleanup

### `docker system prune`

Cleans up unused Docker resources to free up disk space.

```bash
# Remove stopped containers, dangling images, and unused networks
docker system prune

# Remove ALL unused images as well (-a flag)
docker system prune -a

```
